# Stage 5 Report: Documentation PDF, presentation, README, Git packaging

## What I did
* **`docs/Documentation.pdf`** (18 A4 pages) is the mandatory documentation. It covers the design process, the thought process (decision table D1–D11), the final values, Part 1 and Part 2, the verification strategy, how to run everything, limitations and references.
  * Its source is `docs/Documentation.md`. `docs/build_docs.py` converts it with python-markdown to HTML with print CSS, then a headless Chrome print produces the PDF with page numbers.
  * The appendices (the CLI report, the EMANE schedule XML and a platform file) are **inserted from the real generated files** at build time.
* **`presentation/TDMA_Schedule_Optimizer.pptx`** has 19 slides, built with pptxgenjs (`presentation/build_deck.js`). It includes:
  * a theme and three slide layouts;
  * native PowerPoint charts for the benchmark and throughput;
  * figures produced from the real results;
  * speaker notes on every slide.
  * Every number on the slides is read from `presentation/deck_data.json`, which `presentation/make_deck_data.py` generates from `benchmarks/results/`, `outputs/` and `emane/results/`.
* **`README.md`** gives a quick start, input forms, options, exit codes, layout and reproduction commands. **`emane/README.md`** covers Part 2. **`requirements.txt`**, **`.gitignore`** and **`.gitattributes`** are included; `.gitattributes` keeps shell and Python scripts LF so they run in Linux/WSL after a Windows checkout.
* **Git:** a local repository, committed and pushed to GitHub (see `FINAL_REPORT.md` §10).

## Why this method
| Option | Pros | Cons | Verdict |
|---|---|---|---|
| Markdown → HTML → headless Chrome PDF | one readable source (also renders on GitHub), good typography, figures and tables, no extra install | no native math typesetting | **chosen** (equations written in Unicode) |
| LaTeX (MiKTeX present) | best equations | may need package downloads; a second source format | rejected |
| reportlab / fpdf2 | pure Python | layout code for every element | rejected |
| Deck: pptxgenjs with layouts + data file | editable in PowerPoint, native charts, numbers cannot drift | needs node | **chosen** |
| Deck: images of slides | quick | not editable, no native charts | rejected |

## How it works
* `make_figures.py` and `emane/analysis/analyze.py` generate the figures from result files, using the dataviz skill's palette and rules (validated palette, no log-scale bars, sequential single-hue ramps).
* `build_docs.py` fills the `{{GRID_REPORT}}`, `{{GRID_SCHEDULE_XML}}` and `{{PLATFORM_06}}` placeholders from the artefacts and prints the PDF.
* `make_deck_data.py` gathers each metric, for example the E1 delivery, the replication CI and the excess-slot tables, and `build_deck.js` lays out the slides from it.

**Worked example (traceability of one number).** The deck's "99.88 %" for E1 comes from `deck_data.json → emane.E1_optimized.on_mean`. That value comes from `emane/results/summary.json → E1_optimized.on_link_mean = 0.99881…`, which `analyze.py` computes from the 16 `traffic-N.json` files: the unique packets received from each linked sender, divided by the packets that sender sent, averaged over the 84 directed links.

## Results and evidence
* **PDF:** 18 pages. I rendered every page to PNG with pypdfium2 and inspected them. That caught and fixed a cover block that wasn't parsed as Markdown, nested lists that rendered flat, and lists that ran into the preceding paragraph.
* **PPTX:** passes the skill's structural validator ("All validations PASSED"). I exported all 19 slides with PowerPoint COM and checked them visually. That caught and fixed centred titles, a title colliding with the motif, a cover title overlapping its subtitle, clipped code lines, and two over-claims (E4 "without loss" and "TX only in planned slots").
* After the Part 2 corrections, every document carries the same final numbers. I searched for the stale values (99.96 %, 540, 545 752 and "TX only") across the documentation, README and slides and none remain.

## Assumptions and limitations
* The PDF is generated by Chrome's print engine, so a different Chromium version may shift page breaks slightly. The content does not change.
* The presentation uses Cambria and Calibri, which ship with Office. Viewers without them get substitutes.
